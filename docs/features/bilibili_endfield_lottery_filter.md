# 动态抽奖的过滤规则

B 站账号会把社交抽奖混进动态流里，这类内容不是游戏资讯。**默认对所有账号跳过抽奖动态**，
需要时可以收窄到指定账号或整个关闭。过滤只作用于动态，不影响直播与视频订阅，
也不影响手动发送链接的预览。

## 配置

`entari.yml` 的 `plugins.bilibilibot.lottery_filter_uids` 决定生效范围：

```yaml
plugins:
  plugins.bilibilibot:
    # 默认值（不写这一项时同样是这个）：所有账号的动态都过滤
    lottery_filter_uids: "*"
    # 收窄到指定账号（逗号分隔）
    # lottery_filter_uids: "1265652806,12345"
    # 显式留空：关闭过滤，所有动态照常推送
    # lottery_filter_uids: ""
```

按 UID 而不是昵称生效，账号改名不受影响。`*` 与 `all` 等价。
只有显式留空才关闭过滤——不写这一项时按默认值走，即全部账号。

## 判定依据

`plugins/bilibilibot/lottery_filter.py` 按以下顺序判断，任一命中即跳过：

| 依据 | 说明 |
| --- | --- |
| 结构化抽奖节点 | 动态节点类型里带 `LOTTERY`（B 站给互动抽奖标记的类型），节点可见文字不一定写作「抽奖」 |
| 正文抽奖词 | 「抽奖」「开奖」「中奖」「兑奖」及其繁体写法 |
| 赠送描述 | 「抽取 N 位/名 …送出/赠送/获得」这类社交赠送话术 |
| 转发话术 | 「转发/评论/关注/点赞 + 有奖/抽/赢」 |
| 抽奖链接 | 正文里的 `bilibili.com/...lottery` 或 `b23.tv/...lottery` |

判定范围是动态正文、新版 Opus 摘要、富文本节点、附加卡片，以及**转发原文**。
文本先做 NFKC 归一化并去掉空白与不可见字符，全角或零宽写法绕不过规则。
作者昵称与阅读数不参与判定。

### 预约组件的例外

前瞻直播动态常带直播预约卡片，卡片按钮提示写作「预约成功，已参与抽奖」。
这是界面元数据而不是抽奖公告，因此 `ADDITIONAL_TYPE_RESERVE` 的附加卡片整体跳过。
正文与转发原文仍照常检查，不会因此放过真正的抽奖动态。

### 明确不触发的写法

「奖励」「福利」「免费」「寻访」单独出现都不算社交抽奖，避免把游戏内奖励、
卡池说明和签到公告误删。

## 生效位置

- `api/mapping.py` 采集时判定并把原因写入卡片，随队列行持久化。
- `detect.py` 入队前跳过：被过滤的动态仍标记已读并推进游标，不会反复重投，
  也不会挡住后面的正常动态。
- `notifier.py` 发送前复核队列行，过滤器装上之前入队的抽奖动态同样会被丢掉。
- `poller.py` 对生效范围内的账号处理整页动态，而不是只看前五条，避免抽奖挤掉正常内容。

## 已知限制

- 不做图片 OCR：纯图片里的抽奖信息识别不了。
- 纯文本规则：未出现已知表达的新文案需要补充规则。
- 「抽奖」按字面匹配，不区分语境；「本次活动不设抽奖环节」这类否定说法也会被判定为抽奖。
  实际动态里这类文案罕见，暂不为它增加例外。
