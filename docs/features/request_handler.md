# 好友与入群请求（plugins/request_handler）

自动通过好友申请；收到群邀请或入群申请时私聊通知超级用户，由其回复决定。没有命令。

## 行为

| 事件 | 处理 |
| --- | --- |
| 好友申请（`FriendRequestEvent`） | 直接通过 |
| 群邀请 / 入群申请（`GuildRequestEvent`、`GuildMemberRequestEvent`） | 记入待审批，经 `deliver` 私聊通知超级用户（群名、群号、邀请人） |
| 群邀请卡片消息（Ark） | 只私聊通知超级用户；卡片不是系统请求，无法自动通过 |

审批：超级用户在私聊里对**同一个机器人账号**回复。同意：`同意`、`通过`、`接受`、`是`、`yes`、`y`、`ok`、`approve`（或以 `同意`、`通过`、`接受`、`yes`、`approve` 开头）；拒绝：`拒绝`、`忽略`、`否`、`no`、`n`、`reject`（或以 `拒绝`、`忽略`、`reject` 开头）。回复作用于该账号最早的一条待审批请求，处理后回复「已同意/已拒绝加入 …」。

这里的超级用户只取 `basic.superusers` 的第一个；未配置时不通知、不审批。

## 配置

无。

## 数据

待审批请求只在内存里，重启后丢失（之后的回复不再生效）。

## 实测

通知与审批流程在当前连接方式下未实测。
