## 来源与保留边界

| 功能 | 默认数据 | 不变的部分 / 回退 |
| --- | --- | --- |
| 干员搜索、职业/元素目录 | AKE 成长表、物品、中文文本 | 别名与交互选择沿用；管理员目录按名字去重，男女 ID 均可查询 |
| 干员技能、天赋、潜能 | AKE 角色、成长、SkillPatch、效果表 | 数据不完整时整页 FZ，原有 Warfarin 查询入口保留 |
| 武器目录、详情、关联 | AKE 武器/升级/技能/推荐表 | 显式指定 FZ/Warfarin 仍使用指定源 |
| 装备、套装、锻造、属性筛选 | AKE 装备/套装/属性/配方表 | 保留原筛选与锻造规则；缺表整页回退 |
| 配装 | 同一个 AKE 版本内的角色、武器和装备 | 不混用两家数值；失败整套重建为 FZ |
| 抽卡物品名、稀有度、信物、UP 与池名 | AKE 物品/角色/武器/卡池表 | 服务端大保底次数仍取 FZ；无可靠次数标为未知 |
| 奖章、关卡、养成公共表 | 保留原有 AKE 主路径，共用公共 HTTP/磁盘缓存 | 保留既有辅助与降级逻辑 |
| 版本日历 | 有完整当期覆盖清单才用 AKE | 当前内置清单为 1.4，最新为 1.5，实际走官方日历；官方也失败才用明确带版本号的内置回退 |
| 账号、状态、基建、签到、抽卡记录、持有与同步 | 官方账号 API / 本地账号库 | 只替换关联的公共资料，不把个人请求转发给 AKE |
| 帮助、绑定、设置、导入导出、备份、独立预览 | 本地功能 | 流程与权限保持，不因数据源迁移新增写操作 |

已确认的三项数据缺口：

1. 男女管理员天赋含 `{0,0}` 一类缺少参数的描述，共享 SkillData 对应值也为零。拒绝发布残缺页面，由默认路径整页回退。
2. 客户端卡池表没有服务端大保底次数。AKE 提供 UP/名称，但不能据此推测次数；FZ 仍是这个字段的兼容来源。
3. AKE 活动时间不等于全部官方区域/剧情事件的完整清单。禁止把旧内置日历换一个版本标签就当最新。

详情/目录显式指定 AKE 时严格报出该源失败，不悄悄切源。自动回退图片使用备用源自己的缓存键，不缓存成“AKE 完整结果”。

## 结构、缓存与字段兼容

- `providers/repository.py` 用查询上下文固定 `version + sharedRevision`，下游表取同一 `tableCfgPath`。manifest 缓存 60 秒，更新后新查询使用新缓存键。
- `catalog/akedata.py` 只把选中行本地化，转换为现有渲染/计算 DTO。内部借用的 FZ-shaped DTO 和纯构建函数不会发送 FZ 请求。完整 AKE 路径有禁止旧源网络调用的测试。
- 目录无需读约 10 MB 的 CharacterTable；详情才读。I18n 中文表约 11.7 MB，资产索引约 10.26 MiB；索引上限由 8 提到 16 MiB，避免正常文件被误判超限。
- 规范化视图缓存 12 MiB / 128 条 / 600 秒，带版本键、并发请求合并，返回副本防止渲染器修改缓存。PNG 渲染版本更新至 `endfield-card-v42`。
- 新公共表缓存 `data/cache/akedata-tables-v1.sqlite3`，默认 256 MiB / 512 条；`OTAE_PUBLIC_TABLE_CACHE_MIB=0` 可关闭。只接受 HTTPS AKE 版本化 TableCfg URL，无查询参数、无账号头；JSON 校验成功才落盘。与图片缓存分库，支持条件校验、损坏校验、清理隔离和关闭。
- HTTP 原文及解析树 RAM 仍为 API 8 / 表 64 / 素材 24 MiB；表通常保留 600 秒，已有历史表调用可指定更长 TTL，遵守响应缓存限制。磁盘命中仍需解码与内存计量；没有承诺零开销，也未把磁盘写入改成可能丢数据的后台队列。
- `CharBattleTagTable` 用于角色标签；`TermIcon` 目录转为 CDN 的小写 `termicon`。物品优先使用 `ItemTable.iconId` 给出的实际图标，共用素材的装备不再先访问六次错误候选。
- 技能保留普攻各段、处决、下落、技力消耗、冷却、失衡、特殊形态及 Lv9/M1/M2/M3。布局模板不重做；源文本和来源标签不同，不能要求两种数据源 PNG 像素完全相同。
- 复合装备属性按展示槽和 `enhancedAttrIndex` 对齐，一个词条仍是一个锻造槽。配装四维基础值按旧输入的一位小数再执行原计算；保留原有暴伤 50% 等缺省计算约定，不另取第二家数值。
- 抽卡公共目录 schema 2 记录来源与 revision；版本变化或旧 schema 刷新，上游故障允许继续使用已有目录。个人 token、角色状态和抽卡流水不进入公共表缓存。

全量测试 **927 通过、3 跳过、46 个子测试通过**；上一轮为 896 / 3 / 46。另通过 Python 致命错误检查和 `git diff --check`。唯一警告为既有 creart 事件循环弃用警告。

## 实际延迟与代价

以下为同机、同一轮联网单样本，单位秒，旧列为显式 FZ、新列为显式 AKE。包含名称解析、取数据、素材和渲染，不含 QQ 发送；浏览器预启动，图片校验/保存不计入查询耗时。

| 查询 | 完全冷：旧 → 新 | 数据热、重新出图：旧 → 新 | 只保留磁盘：旧 → 新 | 新版连续查询 |
| --- | ---: | ---: | ---: | ---: |
| 提弗洛斯 | 22.717 → 20.243 | 3.708 → 3.413 | 5.483 → 4.884 | 4.6 ms |
| 莱万汀 | 20.528 → 20.401 | 3.358 → 3.606 | 5.536 → 4.828 | 4.6 ms |
| 熔铸火焰 | 3.331 → 3.424 | 1.877 → 0.679 | 2.214 → 2.044 | 17.8 ms |
| 长息轻护甲 | 4.985 → 3.935 | 2.719 → 0.847 | 4.261 → 1.853 | 13.7 ms |

提弗洛斯冷查询本轮缩短约 10.9%，装备仅磁盘场景缩短约 56.5%。也有小幅变慢：武器冷查询约 +0.09 秒、莱万汀热数据重新出图约 +0.25 秒。不能概括成所有功能均提速，更不能以单样本认定统计显著。

四项 AKE 连续查询均零 HTTP。仅保留磁盘时均只请求一次 2,512 字节 manifest，未重下表和图片。此处 `disk_restart` 是清理所有 Python/业务/PNG 缓存并重建 HTTP 连接，**不是重启 OS 或真实新进程**。报告中的 `png_hit` 是紧接着再次查询的测试阶段名；FZ 武器/装备实测仍有上游请求，不代表它们真的命中了整张 PNG。

另外对真实公开职业表启动三个独立进程探测：首次 HTTP 200；新进程读新鲜磁盘零 HTTP；只将临时库改为过期后，新进程 HTTP 304。三轮规范化 JSON 哈希完全一致。这验证了公共表跨进程复用与条件校验，不将该小表的时间算作整页提速。

冷启动下载体积增加：提弗洛斯约 18.37 → 48.33 MiB，武器约 3.29 → 22.14 MiB，装备约 3.37 → 24.17 MiB。AKE 下载共享原始大表，换来后续查询和磁盘复用；慢网络设备首次可能更慢。提弗洛斯大立绘下载问题仍存在，不能把设备上的 33 秒承诺变成秒回。

10 个并发公共数据操作（两名干员、武器、装备、三个目录、长息套组、卡池、信物），没有出图：冷 **2.898 秒**，首次热 **0.354 秒**，后两次热 **12.7 / 12.4 ms**，仅磁盘 **1.474 秒**。三次热轮均零 HTTP，仅磁盘一次 manifest；全部返回 AKEData，34 个池与 1 个信物正常。首次热较慢是部分大表被 RAM 预算淘汰后重新解码，不能只挑最快一轮。

内存：纯数据混合负载 Python 峰值 **429.33 MiB**，末尾规范化视图约 **0.75 MiB**、HTTP 缓存约 **60.30 MiB**；完整图片基准峰值 **1148.02 MiB**，包含基准校验时的 PIL 全尺寸解码但不含 Chromium。预算限制的是缓存驻留，不是进程总内存；本轮不能声称整体内存下降，低内存设备仍需留意大图并发。

上一轮账号实测保留于 [缓存修复记录](endfield_cache_execution.md)：账号状态热查询 2.094 → 0.479 秒，基建 1.001 → 0.319 秒，养成 1.335 → 0.469 秒。本轮不重复使用账号凭据，不把旧账号数据作为新迁移的提速成绩。生产多用户长稳、QQ 端到端、签到/绑定/导入写操作未实测，相关流程依赖回归测试。

发布后从 `refactor/project-architecture` 拉取，按原方式由管理员重启自己的实例才能生效。个别资料可以继续显式指定 FZ/Warfarin；若需要整体回滚，应对本次迁移提交执行 `git revert`，保留架构和上一轮缓存优化，不使用破坏性 reset。没有更改账号数据库 schema，新增的公共缓存可丢弃，不影响账号数据。

字段定义核对使用 AKE 的 [公开 manifest](https://data.akedata.wiki/manifest.json) 与 [原生前端表适配实现](https://www.akedata.wiki/plugin/js/v3-table-data.js)。实现和 fixture 固定记录当时版本，运行时跟随 manifest。
