# 终末地账号绑定流程

`/ef 绑定`（及别名 `/ef 添加账号`）只支持私聊，按提示依次选择服务器、绑定方式，
提交 Token 或手机号与短信验证码，最后选择要绑定的角色。

## 人机验证

国服短信绑定（以及明日方舟 `/ak 绑定` 的短信方式，两边同一套流程）在鹰角风控时，
发短信接口不直接下发验证码，而是回 `status=1`、`msg=需要人机验证`，
并在 `data.captcha` 给出极验 v3 参数 `{gt, challenge, success, new_captcha}`。这时：

1. 机器人用这组 `gt` / `challenge` 生成一个独立的验证页（`otae_bot/hypergryph_captcha.py`），
   页面加载官方 `gt.0.5.0.js`，`api_server` 为 `api.geevisit.com`；页面里没有手机号或账号信息。
2. 把页面上传到临时文件床：先试 0x0.st，失败再试 catbox 的临时盘 litterbox，两边都只保留 1 小时。
   私聊发出：「鹰角触发了人机验证。请用手机浏览器打开下面的链接，完成滑动验证后，
   把页面显示的一整行结果复制发回本对话（勿发给他人）。」并附上链接。
3. 用户在手机浏览器里完成滑动，页面显示一行 JSON
   `{"geetest_challenge":"…","geetest_validate":"…","geetest_seccode":"…"}`，可点「复制结果」。
4. 用户把这一行发回机器人（等待 180 秒）。整行 JSON、`a=1&b=2` 形式、逐行 `键: 值`、
   全角符号和中文引号都能识别；三项缺一项就提示缺了什么并结束本次绑定。
5. 机器人带上 `captcha` 重发短信请求，只传这三个键：
   `{"phone":"…","type":1,"captcha":{"geetest_challenge":"…","geetest_validate":"…","geetest_seccode":"…"}}`。
   发送成功后照常输入短信验证码。

重发后鹰角如果仍要求验证，再给一轮（共两轮）；第三次还要验证就结束，提示稍后再试或改用 Token 绑定。
验证页上传失败时直接结束并给出同样的建议，不会假装短信已发出。
不使用付费打码，也不用无头浏览器代过验证，每次都由用户本人完成。

## 选择角色

账号下只有一个角色时直接绑定。有多个角色时，机器人列出序号、昵称、服务器和 UID：

- 回复列表前面的**序号**，或直接回复列表里的**游戏 UID**，两者可以混用；
- 一次可以回复多个，用空格、逗号、顿号、分号等分隔，例如 `1、3`、`1 1095714689`、
  `UID 1095714689`；全角数字和 `1号`、`1.` 也能识别；
- 回复“全部”绑定列表中的所有角色。

只要有一项不在列表里（序号越界、UID 不属于该账号、其他文字），机器人回复
“编号无效，请回复列表前面的序号（或列表中的 UID）”并重新列出角色，最多询问 3 次；
3 次都无效才取消绑定。

## 取消与超时

每一步都可以回复“取消”（或 `cancel`、`q`、`quit`）退出。两种结束方式提示不同：

| 情况 | 提示 |
| --- | --- |
| 用户回复“取消” | 已取消绑定。 |
| 等待回复超时 | 等待回复超时，绑定已取消；需要时请重新发送 /ef 绑定。 |
| 选择角色连续 3 次无效 | 连续 3 次未选中有效角色，绑定已取消；需要时请重新发送 /ef 绑定。 |

各步骤的等待时间：选择服务器和绑定方式 90 秒、手机号 90 秒、人机验证结果 180 秒、验证码 120 秒、
Token 150 秒、选择角色每次 120 秒。超时时 Entari 会先发送一条“等待超时”。

## 日志

### 步骤日志

绑定的每一步记一条 INFO 日志，前缀 `[endfield-bind]`，包含 QQ 号和步骤名，
不含手机号、验证码、Token、验证页链接或极验结果：

| step | 含义 |
| --- | --- |
| `start` | 开始绑定 |
| `region` | 已选服务器（`provider=cn`/`skport`） |
| `method` | 已选绑定方式（`token`/`sms`） |
| `send_code` / `code_sent` | 请求发送短信验证码 / 已发送 |
| `captcha_required` | 鹰角要求人机验证，`attempt=` 为第几次发短信请求（1～3） |
| `captcha_page_sent` / `captcha_received` | 验证页链接已发给用户 / 收到可解析的验证结果 |
| `verify` / `verified` | 校验验证码 / 校验通过 |
| `token_received` | 收到 Token |
| `roles` | 查到的角色数 |
| `select` / `select_invalid` | 选中的角色数 / 第几次输入无效 |
| `done` | 完成，含新增、更新和当前绑定总数 |
| `cancel` / `timeout` / `invalid` | 用户取消 / 等待超时 / 选择多次无效，`at=` 为所在步骤（人机验证为 `captcha`） |
| `abort` | 手机号、验证码格式不对或未识别的选项，`at=` 和 `reason=` 说明原因；人机验证为 `at=captcha`，`reason=upload`（验证页上传失败）/ `format`（结果无法识别）/ `rounds`（两轮后仍要验证） |
| `failed` | 官方接口报错，含 `operation` 和 `code` |

验证页上传另记 `[hg-captcha] page uploaded host=…` / `page upload failed host=… reason=…`，只有文件床名和失败原因。

### `[message]` 日志脱敏

Entari 内置的 `record_message` 插件会把收到的每条消息写进 `[message]` 日志。
`otae_bot/pipeline/message_log.py` 在启动时给这个日志加了脱敏：

- 所有消息中的大陆手机号显示为 `138****1234`；
- 绑定（以及小黑盒抽卡记录导入）对话进行期间，该用户发来的 4～8 位数字验证码显示为 `******`，
  16 个字符以上、像 Token 的字符串显示为 `<已隐藏>`（发回的极验结果也因此被遮盖）；
- 序号、“取消”、10 位角色 UID 等其他内容照常记录，其他用户和对话结束后的消息不受影响。

插件的交互流程可以用 `otae_bot.pipeline.message_log.sensitive_input(user_id)`
包住需要用户输入凭据的对话。
