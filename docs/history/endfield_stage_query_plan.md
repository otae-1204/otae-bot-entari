# 终末地关卡资料查询实施 Plan

## 状态

- Phase 1 已完成：常驻关卡查询、图片卡、缓存、帮助和测试均已接入。
- Phase 2 已完成：危机合约配置、指标、等级阈值、任务组和商店均已接入类型化扩展。
- Phase 3 已完成：战争回响赛季、轮换周期、难度变体和星级均已接入类型化扩展。
- Phase 4 已完成：AkeData 影拓丰碑系列、普通/苦难变体、敌人与首通奖励均已接入类型化扩展。
- 目录卡超长自动拆图已实现，Phase 2-4 关卡卡已通过实时渲染检查；`CARD_RENDER_VERSION` 已升到 `endfield-card-v36`。
- 第一版只提供游戏内客观关卡资料，不读取账号数据，不包含挑战记录或攻略。
- 用户入口统一使用“关卡”，并接受“副本”作为完全等价的命令别名。

## 目标与边界

### 第一版目标

Phase 1 先完成常驻关卡查询，Phase 2-4 在同一套命令、领域层级和渲染入口上扩展特殊玩法。

首批玩法族：

1. 资源副本。
2. 危境再现与危境碎片。
3. 能量淤积点。

FZ Wiki 当前仅为资源副本提供分类说明，尚不足以形成完整的独立关卡详情。第一版允许它出现在目录中并标记“资料待完善”，但不得用分类说明伪造具体关卡、消耗或掉落。

### 明确不做

- 不要求用户绑定森空岛或鹰角账号。
- 不显示玩家通关状态、最佳队伍、耗时或历史成绩。
- 不提供推荐阵容、配装、打法、强度评价或投稿攻略。
- Phase 1 不包含危机合约、战争回响、影拓丰碑，但基础模型必须能承载后续类型化扩展。
- 不在第一版跨 FZ Wiki 与 Warfarin Wiki 拼接同一关卡的数据。

## 命令契约

### 基础语法

```text
/zmd 关卡
/zmd 副本
/zmd 关卡 <关卡名>
/zmd 副本 <关卡名>
/zmd 关卡 <关卡名> <变体名>
/zmd 副本 <关卡名> 总览
```

具体示例：

```text
/zmd 副本
/zmd 副本 罗丹
/zmd 副本 罗丹 三级
/zmd 副本 罗丹 总览
```

行为约定：

- 不带名称时，返回按玩法分组的关卡资料目录。
- 只给关卡名时，默认返回排序最高的关卡变体。
- 最后一个位置参数与可用变体名精确匹配时，返回指定变体。
- 最后一个位置参数为“总览”时，返回关卡及全部变体的摘要。
- 变体无效时，列出该关卡的有效变体，不静默回退到最高变体。
- `关卡` 和 `副本` 在解析、帮助、错误消息和测试中必须完全等价。
- `/zmd 搜索 关卡 <关键词>` 与 `/zmd 搜索 副本 <关键词>` 进入关卡候选搜索。
- `/zmd <关键词>` 的全局候选解析纳入关卡，但名称冲突时继续复用现有编号选择流程。
- 不新增危境再现、资源副本等平级根命令，也不新增独立快捷命令。

解析时不能简单删除最后一个词。应先用已发现的关卡名做最长匹配，再把剩余的单个词解释为变体或“总览”，避免误伤名称本身带等级词的关卡。

## 领域模型

领域层级固定为：

```text
玩法 → 关卡 → 关卡变体
```

### 公共核心

建议增加独立的关卡模型模块，避免继续扩大现有通用 `models.py`：

```text
plugins/endfield/stages/models.py
```

核心对象：

```text
StageFamily
  key
  name
  aliases
  category
  stage_ids
  extension

Stage
  id
  name
  aliases
  family_key
  summary
  location
  unlock_condition
  source
  source_revision
  variants
  extension

StageVariant
  id
  label
  sort_order
  recommended_level
  stamina_cost
  mechanics
  enemies
  rewards
  extension
```

辅助对象至少包括：

- `StageEnemy`：敌人 ID、名称、图标、等级和可选的生命/攻击/防御。
- `StageWave`：波次、出现条件、出现时间及敌人引用。
- `StageReward`：物品 ID、名称、图标、数量或数量说明。
- `StageSourceRef`：来源名称、条目标题、revision 和更新时间。

`sort_order` 必须由玩法适配器明确生成，默认最高变体不能依赖字符串排序。

### 类型化玩法扩展

公共模型只保留跨玩法语义一致的字段。玩法差异使用明确类型的扩展对象，不使用包含大量可选字段的巨型模型，也不把原始 JSON 传入命令或渲染层。

第一版扩展：

- `BossRushStageDetails`：Boss、系列和深度信息。
- `EnergyDepositStageDetails`：地区、强度、基质和波次信息。
- `ResourceStageDetails`：资源类别；仅在数据源提供具体关卡后承载消耗与掉落。

后续扩展：

- `CrisisContractStageDetails`：指标、依赖、任务和商店引用。
- `WarEchoStageDetails`：赛季、轮换周期、星级与阶段。
- `MonumentStageDetails`：系列、普通/苦难规则和蚀刻章信息。

## 模块与职责

为降低对现有干员、武器和装备查询的影响，新增关卡专用模块：

```text
plugins/endfield/stages/models.py   领域模型与渲染 ViewModel
plugins/endfield/stages/fz.py   FZ 条目发现与原始结构解析
plugins/endfield/stages/service.py  搜索、选择、默认变体和部分资料策略
plugins/endfield/stages/draw.py     目录、详情和总览图片卡
```

现有文件只承担集成：

- `plugins/endfield/catalog/commands.py`：增加 `关卡/副本` scope 和位置式变体解析结果。
- `plugins/endfield/handlers.py`：接入候选收集、渲染分派、缓存和错误消息。
- `plugins/endfield/providers/registry.py`：声明 FZ 支持 `stage`；Warfarin 暂不支持。
- `plugins/endfield/providers/warfarin.py`：复用现有 FZ article/category/search 请求，不增加新的 HTTP 框架。
- `scripts/help_pages.json` 与 `assets/image/help/endfield.png`：补充用户可见语法。

## FZ Wiki 数据适配

### 数据权威性

- 第一版以 FZ Wiki 为唯一关卡权威数据源。
- `--source fz` 可正常工作。
- `--source warfarin` 查询关卡时明确返回“不支持关卡资料”，不得静默改用 FZ。
- 数据源、条目标题和 revision 必须保留到 ViewModel、卡片页脚和缓存键。

### 条目发现

目录索引从 FZ 分类和前缀动态发现，不能硬编码完整关卡名单：

- `category=副本`：危境再现、危境碎片和资源副本入口。
- `category=能量淤积点`：能量淤积点关卡。
- 特定玩法适配器可补充自己的分类或条目前缀。

本地只维护玩法注册表、分类规则和必要别名；实际条目列表走现有 HTTP 缓存。

### 第一版解析器

1. **危境再现**：解析 `wikiTemplateInstance` 中的 `hero` 和 `depths.depths[]`，每个深度映射为一个 `StageVariant`。
2. **能量淤积点**：解析正文摘要与 `wikiIndexTable`，提取地区、强度、推荐等级、基质、武器引用和出怪波次。
3. **资源副本**：当前只解析分类说明并作为目录占位；没有具体关卡与变体时不生成可查询的 `Stage`。

原始字段缺失时遵守三态语义：

- 有值：正常展示。
- 数据源明确为空：按来源事实展示“暂无”。
- 数据源未提供字段：省略板块并标注“数据源暂未提供”，不能转换成 `0`、空奖励或“无敌人”。

## 搜索与选择

- 复用现有拼音、别名、相似度评分和歧义候选交互。
- 候选类型增加 `stage`，显示标签使用“关卡”。
- 关卡索引同时收录正式名称、玩法前缀、Boss 名称和可信别名。
- 关卡与干员、武器或装备同名时不得提高关卡的全局优先级；继续由评分与编号选择解决。
- 作用域查询 `/zmd 副本 <名称>` 只搜索关卡，不混入其他类型。
- 总览和变体选择在关卡完成解析后处理，不参与模糊候选评分。

## 图片卡设计

继续使用现有 `/zmd` 的浅色工业网格、黑黄强调色、中文字体、来源页脚和 HTML 截图管线，不创建独立视觉体系。

### 详情卡

默认展示最高变体，信息顺序固定为：

1. 关卡名称、所属玩法、当前变体。
2. 推荐等级、地区、开放条件和消耗。
3. 关卡说明与特殊机制。
4. 敌人及波次；Boss 可显示生命、攻击和防御。
5. 奖励与掉落。
6. 其他可用变体。
7. 数据来源、revision 与更新时间。

普通敌人以名称、数量、等级、波次和出现条件为主，不默认堆叠所有内部数值。

### 总览卡

- 展示关卡公共信息和全部变体摘要。
- 每个变体显示标签、推荐等级、主要机制和主要敌人。
- 不重复渲染每个变体的完整奖励与敌人数值。

### 目录卡

- 按玩法分组展示常驻关卡。
- 显示可查询数量、资料待完善数量和来源状态。
- 内容过长时由渲染器自动拆成多张图，不增加页码命令。

所有卡片继续采用内容驱动高度、严格最大高度和 overflow 检测。长敌人列表、长机制文本和多变体总览必须进入视觉回归样本。

## 缓存与性能

- 复用 `otae_bot.infrastructure.http.client.fetch_json()` 的 600 秒有界缓存与并发限制。
- 复用现有渲染卡缓存和 singleflight，不增加第二套缓存基础设施。
- 关卡卡缓存键至少包含：渲染版本、数据源、FZ revision、关卡 ID、变体 ID、渲染模式。
- 目录缓存键包含分类规则版本和所有参与目录的 revision/更新时间摘要。
- `CARD_RENDER_VERSION` 在关卡卡语义或布局改变时递增。
- dev 缓存清理范围增加 `stage`，并保持 `all` 能清理关卡缓存。

## 错误与降级

- 未找到关卡：显示查询词，并建议使用 `/zmd 副本` 浏览目录。
- 多个候选：复用现有编号选择流程。
- 无效变体：列出该关卡的有效变体。
- 分类占位：显示“资料待完善”，不进入伪详情卡。
- FZ 超时或异常：返回“关卡数据源暂时不可用”，日志只记录来源、操作和异常类型。
- Warfarin 被显式指定：返回“Warfarin Wiki 暂不支持关卡资料”。
- 图片资源失败：保留文字内容与占位，不让整张卡失败。

## 验收场景

第一版至少通过以下真实场景：

1. `/zmd 副本` 返回按玩法分组的关卡资料目录。
2. `/zmd 副本 罗丹` 返回最高的四级变体。
3. `/zmd 副本 罗丹 三级` 只返回三级详情。
4. `/zmd 副本 罗丹 总览` 返回四个深度摘要。
5. `/zmd 关卡 巨山犼兽` 正确选择两级中的最高变体。
6. `/zmd 副本 能量淤积点·供能高地` 在来源缺字段时不伪造数值。
7. `/zmd 罗丹` 能进入全局关卡候选。
8. `/zmd 副本 罗丹 五级` 返回有效变体列表。
9. `/zmd 副本 罗丹 --source warfarin` 返回明确的不支持消息。
10. 帮助文本、帮助图片和命令错误提示覆盖全部新语法。

## 分阶段实施

### Phase 1：公共基础与常驻关卡（已完成）

1. 增加关卡模型、FZ 发现器和候选索引。
2. 接入危境再现与危境碎片。
3. 接入能量淤积点。
4. 增加目录、默认最高变体、指定变体和总览。
5. 增加图片卡、缓存、帮助与完整测试。
6. 保留资源副本目录占位，等待可验证的具体关卡数据。

### Phase 2：危机合约（已完成）

已增加危机合约类型化扩展，解析 `overview / levels / board / tasks / shop`；命令入口和公共模型不变。实时公开数据已核对 3 个配置、46 个指标、3 组等级阈值、3 个任务组和 1 个商店。

### Phase 3：战争回响（已完成）

已增加赛季、轮换周期、关卡和星级扩展，解析 `cycles / stages`；命令入口和公共模型不变。实时公开数据已核对每关普通/困难/残酷 3 个变体、3 期轮换和 9 星上限。

### Phase 4：影拓丰碑（已完成）

已接入 AkeData 公开静态表作为影拓丰碑的客观数据源，并保留 FZ 与 AkeData 的来源边界。Manifest 动态解析当前表版本，不硬编码版本目录；`DungeonSeriesTable` 与 `DungeonTable` 建立系列、关卡和普通/苦难变体，奖励、敌人与属性表补充机制、推荐等级、最终敌人面板、抗性、失衡值和首通奖励。最终敌人面板会合并等级模板、敌人实例修正与场景出生 Buff；失衡恢复时间及其系数保持为独立字段。2026-07-27 实时核对结果为 6 个系列、25 个关卡、50 个难度变体；默认目录合并 FZ 与 AkeData，显式 `--source fz|akedata` 仍保持隔离，自动候选携带来源并按该来源渲染。全程不读取玩家挑战记录、账号数据或攻略内容。

## 实施约束

- 不修改或清理当前工作区内与本功能无关的账号 UI、抽卡、脚本、素材和实验文件。
- 实现前重新检查 `git status --short --branch -uall`，只触碰本 Plan 列出的关卡相关文件。
- 不自动启动、停止或重启机器人进程。
- 不把任何账号令牌、森空岛凭据、原始个人响应或内部用户标识引入关卡查询链路。
