# 终末地账号 UI 复刻规格

更新时间：2026-07-15

## 目标

基于用户提供的游戏内个人名片、影拓丰碑关卡页和危机合约结算页，建立三套可替换数据、可输出 PNG、可继续接入 Bot 的 16:9 HTML/CSS 模板。

复刻对象是视觉语言、信息比例和布局逻辑，不把参考截图作为整页背景，不保留截图中的原账号数据。所有人物、奖章、装备、武器、活动和敌人素材来自当前森空岛 API 响应。

## 共同画布

- 危机合约与影拓丰碑输出尺寸：`1920 × 1080`。
- 个人名片从原始 `1920 × 1080` 坐标系中仅裁掉顶部 `82px` 和左侧 `220px`，输出 `1700 × 998`；内部元素不缩放、不拉伸、不重新分配比例。
- 画面密度：桌面游戏 HUD，不使用普通网页导航、卡片栅格或移动端组件。
- 字体：标题和正文使用随插件打包的 `HarmonyOS Sans SC`，数字/HUD 使用 Bahnschrift 与 Arial Narrow 近似游戏中的 Novecento/Iosevka 窄体观感。
- 图标：个人页角色职业、属性和潜能角标全部使用本机游戏资源中提取并固化到 `plugins/endfield/assets/ui/` 的原始 PNG；危机指标继续使用森空岛/Warfarin 返回的真实指标图源。
- 共同纹理：斜向扫描纹、细网格、技术标线、重复刻度、局部噪点感。
- 共同形状：矩形、切角、细边框、短圆角；仅游戏内按钮和浮层使用较大圆角。
- 共同层级：官方资源图作为场景层，半透明色幕作为氛围层，信息面板作为 HUD 层。

## 个人名片

- 左侧约 40%：头像、角色名、等级、主线、三项收藏统计和地区等级。
- 右侧约 35%：奖章展示条、四名展示干员和状态短句。
- 中部保留大面积场景透气区，避免普通 Dashboard 的均匀分栏。
- 主色为煤灰、雾白和荧光绿；橙色只用于头像框和少量警示。
- 森空岛未提供参考截图中的完整名片背景，因此个人页保留最初版绿色场景回退；头像、干员、奖章和小图标仍使用真实资源。
- 奖章槽位按 API 展示位交错映射：奇数位在上层、偶数位在下层，形成上下紧贴的蜂窝排列。
- 奖章背景按游戏原始三层结构组合：左侧 `deco_friend_card_medal_05` 圆环/立方体装饰、中央单层 `bg_friend_card_medalentry` 浅色凹槽，以及右侧 `bg_friend_card_medal` 黄色分界与深色凹槽；中央槽位与实际奖章使用同一定位基准。
- 头像下方白色圆形按钮与右下主题操作组不进入最终输出。

## 影拓丰碑

- 左侧固定关卡序列，选中项白底反相。
- 右上为当前关卡名、推荐等级和关卡描述。
- 右中为机制特性，右下按参考图使用折叠敌方情报、最佳记录和挑战状态；API 不提供奖励预览时不伪造奖励。
- 主色由主题图决定，叠加紫灰和暗红色幕；通过状态使用绿色窄条。

绑定账号数据页采用独立的白色工业档案 HUD，不复用公共关卡资料卡。

影拓丰碑三张图各自的结构：

- **总览**：左栏是**主题海报位**（整张供 KV）+ 其下一块墨色台座（总进度巨字、琥珀进度轨、普通/苦难两行完成数与真实推导的「最快 / 合计」）；主区关卡表 `# / 关卡 / 两档「用时 + 队伍」`；历届主题横排成碑面胶片条置于表下，每块分开标注 `普通 4/4` 与 `苦难 4/4`，当前主题以琥珀底加顶条标出、其余静默。
- **详情（碑面双档）**：题头给关卡名与 `BEST CLEARED`；左栏并置同关普通/苦难两条记录（难度名做主字、推荐等级降为副行、记录日期与用时叠在右上角一栈、配队四格按栏宽等分铺满整行、成员不足补空框）；中栏把官方机制串接段拆成条目（仅本档独有的一条染成该档身份色，图例写「苦难独有」）；右栏单列敌方情报（等级按档取，说明取首句不截半句）；底部标主题周期与活动状态。
- **历史**：每页两个主题，分页器住在页眉右端（`MONUMENT / ARCHIVE` + `1 / 3 页` + `本页 X 个主题`），不单独占一条 band，也不写 `ARCHIVE 02` 这种会被读成档案编号的本页条数；每块主题各按自己的关卡数定高；档案头是**纹章 + 铭牌**（章在左，右侧上下两行 `THEME ARCHIVE` 与主题名——章名就是主题名，所以纹章跟着身份行走，不跟成绩走；铭牌两行刚好接住 56px 的章，章图透明边对称、偏移为 0，看着不齐是排版问题不是图的问题），周期只到日期（`2026-08-06 → 08-20`，同年省第二个年份），镀层靠另一张章图表达故不写「· 已镀层」，深色章靠极淡光晕从墨底抬起。

共同遵守的规则：

- **不画通关勾**：有用时本身就是通关的证据，状态由数据是否存在来表达；整档无记录时只写一句「未通关」，不铺「— / 用时未返回 / 队伍未返回」三条空话。
- **难度身份色成阶梯**：影拓为 普通墨 / 苦难官方玩法条红 `#d64035`；战争回响为 普通墨 / 困难钢青蓝 / 残酷同款红。脊线、难度名、机制独有标记共用这一套色。
- **列头压在用时轨的正中**：用时单独占一条轨道并居中，列头对齐的是速度数字而不是整组数据；第二轨要额外让出 13px（1px 分隔线 + 12px 内缩），否则列头偏左约 14px。
- **头像按行高自适应**：关少则大、关多则收，上限同时受格宽约束以免溢出列外；取图失败时留虚线空框且不带潜能角标，不把内部 charId 片段印到图上。
- **卡宽按内容算**，不写死 1920：影拓历史 `_monument_history_width()`（实测 1569×934）、空态 1320，高度随内容生长。
- **不排三等宽指标卡**，也不让题头与表格复读同一对数字：题头答代表作（`BEST CLEARED` = 最高已通关档），表格答逐档明细。
- **空态是一张查询回执**：左联存根只写页眉没有的三行（玩法 / `接口结果 成功（code 0）· 无可见记录` / 查询时间），并盖一枚跟随主色的「无记录」章；右联给结论、两种真实原因（还没打过 / 森空岛未开启展示，依据 `docs/skland_endfield_public_query.md` 的实测结论并列而不武断）与下一步。不写「不会用虚构的 0% 填充页面」这类说给开发者看的话。
- **不拿单个主题的 KV 当多主题页的背景**；影拓主题图是 960×1200 纸本水墨竖构图海报，只在总览整张供在纸色海报位上（不裁切、不压暗幕）。

## 战争回响

- 总览显示当前赛季星数、追加目标、当前轮换每个关卡组的**最高通关档**状态（不是三档并列）、最近最佳队伍与荣誉摘要。
- 详情页以「**本组三档对照**」为主结构：题头给关卡组名、当前难度、星级与追加目标（星级与追加目标是关卡组级的，不逐档重复），右侧 **`BEST CLEARED` 大字给「最高通关档」的成绩**（按 残酷>困难>普通 取第一个已通关档，副行标明是哪一档与记录时间；全没过写 `-- / 尚无通关记录`，过了但没给用时写 `用时未返回`，不编数字）——题头答代表作，表格答逐档明细，两者不复读同一对数字；左栏并置同组的普通/困难/残酷三条记录，**难度身份色成阶梯**（普通墨、困难钢青蓝、残酷官方玩法条红），每档带自己的推荐等级、记录日期、用时与配队四格；三档的 `name` 往往完全相同，当前档只能按对象身份 + 难度判定，否则三行会一起反相；中栏把机制串接段拆成条目（标记形状统一，仅本档独有的一条染成该档身份色，图例写「困难独有 / 残酷独有」），右栏单列敌方情报（等级按档取，说明取首句不截半句）。
- 历史页按赛季分页，每页覆盖该赛季所有轮换和个人通关状态；赛季名称、时间和 KV 始终以实时接口字段为准。
- 输出宽度按内容算：影拓总览与详情 1920、影拓历史 1569（`_monument_history_width()`），高度随内容生长（上限 6000 只是兜底），不再声称统一 1920×1080；群聊 UID 使用遮罩，私聊显示完整公开游戏 UID。
- 个人挑战原型提供 A/B/C 三种 KV 占比（20% / 34% / 55%，B 为正式默认）与对应不透明度（.30 / .42 / .58）；三者共享同一份脱敏接口数据与布局骨架。

## 危机合约

- 左侧约 48%：行动成功、指标、用时、指标矩阵和奖章提示。
- 右侧约 46%：四名干员纵向大卡、武器和四装备槽。
- 主色为高饱和危机红、炭黑和冷灰紫，黄色仅用于指标和装备等级。
- 结算页强调大数字和硬分区，不使用柔和阴影或玻璃拟态。
- 零额外潜能直接使用官方 `potential_0` 星标/单黄色杠图；不自制横杠或暗化星标。
- 结果数值区保留小型前景图标，并叠加同源深色大水印；武器下方四件历史装备必须完整显示。
- 最终输出移除左上“行动结束”、干员职业角标、右下三按钮以及左下延迟/UID，仅保留底部装饰刻度。

## 数据边界

- 主页显示公开游戏 UID（`roleId`），不显示森空岛内部用户 ID、认证凭据或绑定响应中的其他敏感字段。
- 角色展示遵循 `config.charIds` 顺序，缺失时按等级和稀有度回退。
- 奖章展示遵循 `achieve.display`，并按等级/镀层选择图标。
- 影拓丰碑优先选择当前活动主题，并选择一个困难关卡作为复刻主视图。
- 危机合约先用 `bestRecord.id` 请求 `/api/v1/game/endfield/card/crisis-contract/record`，角色名和职业等静态元数据按 `charId` 补齐，但武器、三词条等级、装备、等级和潜能必须使用历史记录快照，禁止回填当前配装。
- 所有远程资源加载失败时保留布局，不让整页渲染失败。
