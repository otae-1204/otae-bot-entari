## 结论与代价

同一账号的真实重复查询：账号状态约快 77%，基建约快 68%，养成统计约快 65%。影拓丰碑、战争回响和奖章进度的底层个人接口约快 83%–87%，主要是复用仍有效的签名凭据，**每次仍请求新的个人数据**。

不是所有场景都变快：

- 三类账号页冷缓存增加约 0.25–0.48 秒。首次解析、内存计量及公共图片持久化有成本。
- 上游缺失图片的装备详情/目录不再缓存不完整 PNG；相同缺图查询需要重新尝试并出图，本次热查询分别约 2.69 / 4.55 秒。不能把原来的“直接返回缺图缓存”作为等价的健康命中。
- 混合联网热查询约快 51%，但四组混合请求整批由 2.01 秒变为 2.40 秒，没有并发提速结论。
- 同样 14 类用例的单轮顺序回放，Python 峰值 RSS 693.92 → 732.59 MiB，增加 38.67 MiB（约 5.6%）；不包含 Chromium，也不代表长期生产内存。没有宣称总内存下降。

## 修复清单

| 项目 | 实施与验证 |
| --- | --- |
| C01 清理与在途任务 | 缓存发布绑定任务身份；按范围清理会隔离旧任务，新查询不再等待旧任务；磁盘发布同样校验清理代次。已有等待者允许完成，但不能覆盖新缓存。 |
| C02 取消与退出 | 调用者取消不取消共享下载、不造成重复下载；缓存持有任务并回收异常，退出取消并等待自有任务；共享 HTTP 生命周期覆盖事件循环退出。 |
| C03 失效依赖 | 全清理覆盖 HTTP/AKEData、名称映射、养成目录、挑战本地化、关卡/日历、图片、配装及账号成品图；图标清理覆盖对应图片和成品。派生数据的清理代次阻止旧请求回填。 |
| C04 统计 | 区分直接命中、等待合并、过期、容量淘汰、过大条目和失败；增加下载/解析/等待、磁盘命中和 304 诊断。清理时按命名空间重置诊断统计。 |
| C05 容量 | 公共 API / AKE 数据表 / 图片分别使用 8 / 64 / 24 MiB 内存预算；JSON 原文与解析树都计量，不再仅统计原始字节。详见下方容量边界。 |
| C06 请求共享 | AKEData 公开请求统一 URL、分钟版本参数、请求头和命名空间，减少重复取大表；实际请求头指纹隔离 Cookie/认证上下文，客户端 Auth 流绕过共享缓存。 |
| C07 解析复用 | JSON 首次解码一次；End 公共读取复用只读 dict/list 兼容树，默认通用接口仍返回独立可变副本；名称、养成、关卡和抽卡目录减少重复解析。 |
| C08 成品正确性 | 公共卡片保留渲染版本键；挑战图增加原始数据/身份/素材代次/本地化版本键；缺图或降级卡片不驻留。修复奖章分页高度处理的两个未定义函数调用。 |
| C09 账号图片复用 | 状态/基建/养成先获取新数据、完成权限和视图构建，再按完整视图哈希、角色/服务器、群聊/私聊、素材代次、渲染版本复用 PNG；只存内存，TTL 60 秒。 |
| C10 公共图片磁盘层 | 新增公共图片白名单 SQLite 缓存：256 MiB 图片内容、最多 4096 项、LRU、SHA-256 完整性校验、事务替换、清理代次；真实新进程命中验证通过。旧抽卡文件目录的边界见下文。 |
| C11 条件验证 | 磁盘图片过期后使用 ETag 或 Last-Modified，304 复用原内容；遵守原截止时间及 no-cache/private/no-store；真实上游 304 验证通过。没有扩大私人状态 TTL。 |
| C12 抽卡/流水 | 抽卡批量查重和事务 upsert，流水分类减少重复分配，抽卡公共元数据增加内存复用及图片过期/清理检查；个人查询复用有效凭据，认证失效仅刷新重试一次。完整同步、分页和备份语义保留。 |

默认通用 JSON 接口返回可变副本，而非将只读树强加给其他插件。只读树保留 `isinstance(dict/list)` 兼容性；普通修改会报错，确需修改时可使用默认接口或 `deepcopy`。

### 混合负载、失败样本与内存

每组混合查询同时运行配装、武器关联、奖章公开数据、关卡目录；四组即 16 个业务子任务。

- 完整联网样本：冷 3.757 → 3.309 秒，热 157.9 → 76.8 ms；四组整批 2.011 → 2.400 秒。
- 基线混合冷请求 31 次；实现完整样本为 30 / 29 / 29 次，响应字节约从 28 MB 降至 16 MB，避免重复下载大表。
- 后续 mixed-only 联网复测在 FZ Wiki 超时处中止，报告保留部分样本和错误，不计算失败轮的中位数、不替换为 0。
- 初轮干员目录遇到 FZ 超时，表中使用单独完整复测；初轮基线关卡脚本误用了 `item.key`，已改为 `stage_key` 并完整重测该项。原始错误报告均保留。
- 两版本顺序执行同样 14 类公开回放，各 1 冷、1 热、1 批四并发，42 组输出一致。奖章比对只排除本地采集时间 `fetched_at`，没有排除源数据字段。
- 上述全回放 Python 峰值 RSS 693.92 → 732.59 MiB；只是一轮相同工作负载的高水位，不含 Chromium、不能当作生产总上限。实时 mixed-only 复测失败，未拿不同用例组合的 RSS 混做前后对照。
- 分池和解析树计量可能使小 API 条目更早被淘汰：全回放末尾 mixed 热查询出现基线 0 / 实现 4 次公开请求；不能承诺每种负载的请求数量都减少。

小样本联网测试受 CDN、限流和上游实时更新影响，不给出“全插件平均提速”或统计显著性承诺。长时间驻留、真实多用户混合负载、QQ 端到端、签到/绑定/导入写操作没有实测；这些功能依赖自动化回归，本轮没有用账号执行写操作。

## 公共缓存跨进程验证及容量

对一张真实 AKEData 公共图片，在临时缓存目录中启动三个独立进程：

| 阶段 | 实际 HTTP | 内容 |
| --- | --- | --- |
| 首次读取 | 200，下载一次 | 160,336 字节 |
| 新进程、磁盘仍新鲜 | 0 次请求 | 完全相同 |
| 仅将临时缓存时间改为过期后再启动 | 304，条件校验 | 完全相同 |

这项探针只用于确认行为，运行时也有回归测试负载，不以其单次耗时计算性能百分比。自动化另测 no-store/private、隐式 Cookie/Auth、原截止时间不续期、坏哈希删除、容量淘汰和清理期间旧请求不可回填。

默认设置（MiB）：

| 配置 | 默认 | 作用 |
| --- | ---: | --- |
| `OTAE_HTTP_API_CACHE_MIB` | 8 | API 原文与解析结果 |
| `OTAE_HTTP_TABLE_CACHE_MIB` | 64 | AKEData 表原文与解析结果 |
| `OTAE_HTTP_ASSET_CACHE_MIB` | 24 | HTTP 图片字节 |
| `OTAE_PUBLIC_IMAGE_CACHE_MIB` | 256 | 磁盘公共图片内容；设 0 可关闭 |
| `OTAE_PUBLIC_IMAGE_CACHE_PATH` | `data/cache/public-images-v1.sqlite3` | 可丢弃的公共图片缓存位置 |

内存三池总预算 96 MiB，不包括其他业务/PNG 缓存、仍被派生对象引用的源树、在途响应、Python 分配器与浏览器。磁盘 256 MiB 限制的是图片内容，SQLite 索引/WAL 有额外开销。旧抽卡图片目录暂未整体迁移到这个磁盘预算：本轮增加了 TTL、清理标记和派生图源时间检查，但**不能宣称所有历史缓存文件已统一限容**。

磁盘白名单只接受指定公共 HTTPS 图片路径，拒绝带查询参数/认证头和私人 API；保存哈希键、图片和公共验证器，不保存请求 URL、账号标识、Token、Cookie、档案 JSON 或私人 PNG。官方个人数据只用于当前内存查询；程序自身已有加密账号存储机制未改动。
