# 双游戏签到合并：`/ak 签到` 与 `/ef 签到`

没有独立的统一签到命令。用户发 `/ak 签到` 或 `/ef 签到` 时，先按选择器签到**当前命令对应的游戏**；
如果同一 QQ 还绑定了另一款游戏，并且本群没有关闭它，就接着签到另一款游戏的**全部已绑定角色**，
两张结果卡上下拼成一张图片发送。终末地与明日方舟继续使用各自的 `data/` 数据库、各自的凭据密钥和
各自的 HTTP 客户端。

## 命令

| 命令 | 说明 |
| --- | --- |
| `/ak 签到 [全部\|编号\|昵称\|UID后四位]` | 选择器只作用于明日方舟；若还绑定了终末地，顺带签到终末地全部角色 |
| `/ef 签到 [全部\|编号\|昵称\|UID后四位]` | 选择器只作用于终末地；若还绑定了明日方舟，顺带签到明日方舟全部角色 |

## 行为

| 情况 | 行为 |
| --- | --- |
| 同时绑定两个游戏 | 当前游戏按选择器签到，另一款签到全部角色；当前游戏的卡片在上，合成一张图片 |
| 未绑定另一款游戏 | 只发送当前游戏的卡片，**不**提示“未绑定”“已跳过” |
| 本群关闭了另一款游戏 | 不查询、不签到另一款游戏，也不提示；不会绕过群开关。私聊没有群开关 |
| 当前游戏未绑定或选择器无效 | 只回复当前游戏的原有提示，不会顺带签到另一款游戏 |
| 另一款游戏整体失败（如缺少密钥、数据库异常） | 当前游戏照常出图，另一款的失败原因附在同一条消息里 |
| 某个角色失败或登录过期 | 该角色在自己的卡片里显示失败原因，其余角色与另一款游戏继续 |
| 今天已经签到 | 正常显示“今日已签到” |
| 某张卡片渲染失败 | 该游戏的完整文字结果随另一张卡片一起发送；两张都失败或拼接失败时整体回退文字 |
| 图片发送失败 | 再发送一次两款游戏的完整文字结果，**不会**重新执行签到请求 |

每个游戏独立捕获异常：数据库异常、密钥缺失、接口错误都不会阻断另一个游戏。绑定记录先查、凭据后解密，
未绑定另一款游戏的用户不会收到那款游戏的密钥错误。

## 结构与复用

- `otae_bot/attendance_registry.py`：共享注册表与调度循环，只依赖 `otae_bot.*`，
  不导入任何 `plugins.*`（`tests/test_architecture.py` 会校验这一点）。
  `collect_companion_outcomes` 跳过当前游戏，只返回另一款游戏真正的结果或失败；
  未绑定、群内关闭、插件未加载的游戏不产生任何输出。
- `otae_bot/attendance_delivery.py`：在共享图片线程池中拼接 PNG，按较窄图片等比缩放，
  不放大、不裁掉账号行；拼接结果超过 16384px 高或 3200 万像素时回退完整文字。
  `deliver` 先把图片和必要说明放在同一条消息里发送，图片发送异常时改发一次完整文字。
- 两个游戏插件在**加载时**各自注册一份能力（游戏标识、查询绑定角色、签到全部角色、
  生成图片和文字结果），供另一款游戏的签到命令调用。插件之间不互相导入 `handlers`，
  避免重复注册命令和初始化副作用。
- 注册按游戏标识覆盖，热重载不会残留旧实例；插件被真正卸载时，
  `otae_bot.application` 监听 `PluginUnloaded` 清理对应注册；回调参数显式标注事件类型，
  使 Entari 注入卸载事件，避免误收应用实例而漏清理。
- 群开关沿用各游戏插件自己的键（`arknights`、`endfield`），用命令所在的机器人账号与群判断。
- 防重锁沿用原实现：明日方舟使用 `plugins.arknights.tasks.ROLE_TASKS`，
  终末地使用 `plugins.endfield.gacha.service.ROLE_TASKS`。因此 `/ak 签到` 与 `/ef 签到`
  同时执行时，同一角色只会提交一次签到请求。
- 卡片样式与单游戏签到完全一致：终末地采用新版圆角布局、黄绿底线和累签里程碑；
  明日方舟保留蓝黑头部与亮蓝底线，奖励使用已审核的本地图标。

## 帮助

`/help 签到`、`/ak 帮助`、`/ef 帮助` 都注明：绑定了另一款游戏时会顺带签到它的全部角色。

## 测试

`tests/test_signin_registry.py` 使用临时数据库与模拟接口覆盖：`/ak 签到` 与 `/ef 签到` 的选择器只作用于
本游戏、另一款签到全部角色、当前游戏在上的拼图、未绑定另一款时无提示、群开关不被绕过、
图片发送失败只回退文字不重复签到、渲染失败回退文字、一个游戏异常另一个仍完成签到、
同一角色不重复提交、热重载与卸载后的注册清理。
`tests/test_attendance_delivery.py` 检查拼接顺序、缩放、图片预算、文字回退与发送重试，
`tests/test_architecture.py` 通过真实 Entari 事件确认已没有 `/签到` 命令、两款游戏的签到命令都拿到
机器人账号（用于判断群开关），并验证插件卸载、重新加载与能力注册。

运行 `scripts/render_signin_preview.py` 可生成使用实际渲染器和拼接函数的预览，
覆盖 `/ak 签到` 双游戏成功、`/ef 签到` 各 3 个账号、另一款游戏整体失败、单角色失败与未绑定另一款；
数据为样例，不读取真实凭据、不调用游戏接口，仅通过正式图片加载链路获取终末地的公共奖励图标。
加上 `--case six-accounts` 可单独生成 `/ef 签到` 下终末地 3 个角色与明日方舟 3 个角色的合成图。
