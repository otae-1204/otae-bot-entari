# 群内功能管理

`group_manager` 随机器人自动加载，无需额外配置。更新代码并重启后即可使用。
所有功能默认开启，按整个插件控制。

在需要管理的群内发送：

```text
/功能 列表
/功能 关闭 hyw
/功能 开启 hyw
/功能 关闭 ef
/功能 开启 steam
```

`/功能` 查看用法，也支持 `/插件`、`/plugin`。插件名大小写不敏感，
可使用 `/功能 列表` 中的完整插件名，或者以下别名：

| 插件 | 常用别名 |
| --- | --- |
| `hyw` | `q`、`何意味` |
| `grok_bot` | `grok`、`grokbot` |
| `endfield` | `ef`、`终末地` |
| `steamInfo` | `steam` |
| `bilibilibot` | `bili`、`bilibili` |
| `minecraft_plugin` | `mc`、`minecraft` |
| `mcsm` | `mcsm` |
| `tibo_radar` | `tibo`、`雷达` |
| `McModQuery` | `mod`、`模组` |
| `McWikiQuery` | `wiki` |
| `eft_helper` | `eft`、`塔科夫` |
| `forkout` | `fork`、`叉出去` |
| `peek` | `窥视` |
| `help_plugin` | `help`、`帮助` |

只有 `.env` 中 `SUPERUSERS` 配置的用户、本群管理员或群主可以执行管理命令，
包括查看状态。普通成员无法修改开关，SuperUser 也必须在目标群内执行。
命令不接受群号，不能通过私聊或另一个群修改目标群的配置。
管理员信息优先读取本次事件的角色，缺失时通过当前机器人账号查询成员信息；
QQ 桥接缺少 Satori 角色时，会使用同一账号的 OneBot 内部接口核验。
无法确认权限时拒绝操作。

关闭一个插件后，该插件在当前群的命令、消息自动解析等监听不再触发，
订阅推送也不会向该群发送。其他插件、其他群及私聊继续使用各自的设置。
已开始处理的请求可能完成回复；开关不会中止已经运行的请求。
群开关不会删除订阅、解绑账号或清空插件数据。后台轮询仍服务其他群，
重新开启后恢复后续处理，不保证补发关闭期间的推送。

开关按「平台 + 机器人账号 + 群号」独立保存到
`data/group_manager/switches.json`，立即生效，重启后保留。无需修改 `.env`。
多机器人接入时，只修改接收命令的机器人在本群的设置。
如需手动编辑开关文件，请先停止机器人；格式错误会拒绝读取和覆盖，
需修复文件后重启。数据文件应随运行数据一起备份。

`group_manager` 始终可用，以便重新开启已关闭的插件；负责好友及入群审批的
全局 `request_handler` 不提供群开关。插件原有的权限、白名单和订阅配置仍生效，
开启插件不会绕过这些限制。系统启动、清理及全局任务不受群开关影响。
